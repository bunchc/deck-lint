# Operational Hygiene Rules

Operational hygiene rules are designed to enforce best practices for maintaining a clean, secure, and reliable API gateway configuration. These rules help prevent common operational issues, reduce security risks, and ensure that the gateway is easily auditable and maintainable. By adhering to these guidelines, you can avoid misconfigurations that lead to downtime, security vulnerabilities, and unpredictable behavior.

This category includes rules that enforce explicit route matching, prevent the use of wildcard hosts, and ensure that all resources are properly configured and secured. Adhering to these rules is essential for maintaining a healthy and stable API gateway.

## Rules

| Rule File                                                                          | Name                                   | Description                                                                                                                                      |
| ---------------------------------------------------------------------------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| [`avoid-kongclusterplugin-overload.yaml`](./avoid-kongclusterplugin-overload.yaml) | `avoid-kongclusterplugin`              | Discourages using `KongClusterPlugin` in Gateway API environments to prevent unintended side effects, recommending more explicit plugin scoping. |
| [`disallow-unused-consumers.yaml`](./disallow-unused-consumers.yaml)               | `disallow-unused-consumers`            | Flags consumers that are not associated with any credentials or ACLs, reducing security risks and configuration clutter.                         |
| [`enforce-kic-gateway-mapping.yaml`](./enforce-kic-gateway-mapping.yaml)           | `kic-gateway-mapping`                  | Ensures a one-to-one mapping between a KIC instance and a Gateway resource to promote deterministic behavior.                                    |
| [`enforce-real-ip-forwarding.yaml`](./enforce-real-ip-forwarding.yaml)             | `enforce-real-ip-forwarding`           | Requires forwarding the real client IP address from the load balancer to Kong to ensure accurate client identification.                          |
| [`enforce-resource-limits.yaml`](./enforce-resource-limits.yaml)                   | `enforce-resource-limits`              | Requires that resource limits and requests are applied to Kong control and data planes to ensure stable resource allocation.                     |
| [`no-wildcard-hosts.yaml`](./no-wildcard-hosts.yaml)                               | `no-wildcard-hosts`                    | Prevents the use of wildcard hosts in routes to avoid overly broad request matching and potential security risks.                                |
| [`prevent-open-proxies.yaml`](./prevent-open-proxies.yaml)                         | `prevent-open-proxies`                 | Enforces explicit service and route matching to prevent Kong from acting as an open proxy, which can be a security risk.                         |
| [`require-catch-all-route.yaml`](./require-catch-all-route.yaml)                   | `require-catch-all-route`              | Mandates a default catch-all route to safely handle unmatched requests and prevent unexpected routing behavior.                                  |
| [`require-dedicated-gatewayclass.yaml`](./require-dedicated-gatewayclass.yaml)     | `gatewayclass-unique-controller`       | Enforces the use of a dedicated `GatewayClass` for each Kong Ingress Controller (KIC) deployment to ensure tenant isolation.                     |
| [`require-explicit-route-matching.yaml`](./require-explicit-route-matching.yaml)   | `require-explicit-route-matching`      | Ensures that routes have specific matching criteria (e.g., hosts, paths, or methods) to prevent unpredictable routing behavior.                  |
| [`require-readiness-probes.yaml`](./require-readiness-probes.yaml)                 | `readiness-probes-request-termination` | Mandates the use of readiness probes with the `request-termination` plugin for reliable health checks and graceful shutdowns.                    |
